## Clock actions and an opt-in live device clock

The live **Device date and time** entity is now disabled by default for newly added devices. With it disabled, the integration no longer polls RTC parameters 111/112, avoiding continuous clock state changes in Activity and Recorder history.

**Existing installations:** Home Assistant preserves your entity settings. After updating, open the Freshpoint device, select **Device date and time**, open its settings and turn off **Enabled** to stop its clock updates. Do this for each Freshpoint unit. Already recorded history is not deleted. If you enable the entity again, live polling and the resulting Activity/history entries resume.

### New automation actions

- **`freshpoint.set_current_datetime`** copies Home Assistant's current local date and time to one or more selected Freshpoint devices.
- **`freshpoint.set_datetime`** sets a supplied date and time on one or more selected devices. Years 2000-2099 are supported. Values without an offset use Home Assistant's timezone; offset-aware values are converted to that timezone.

Both actions remain available when the live clock entity or button is disabled. Find them in the automation action picker or **Developer tools → Actions**. Select the devices in the required **Freshpoint devices** field; `set_datetime` additionally requires **Date and time**.

The existing **Set current time** button uses the same internal clock-setting method as `set_current_datetime`; its entity ID is unchanged. Setting the clock can affect a device's weekly schedule. This release does not change Recorder/Activity filters globally or automatically synchronize clocks.

### Verification

Protocol, polling, action schema and isolated coordinator/action tests cover the changes. Home Assistant runtime and physical clock-write verification remain pending; no device settings were changed during development.

### Release publishing

Merges into main now run validation and automatically publish a matching version tag and GitHub Release with these notes. Already published versions are skipped. HACS can then show the release version and announcement after refreshing repository information.
